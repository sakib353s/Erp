# 13. REPORTS — Traceability

Baseline (`BL`) applies. Spec §34: **server-side report services** (not SQL fragments in controllers); every report supports date range, branch scope, user/role scope, product/customer/supplier filters, payment method, status, export, print, PDF, pagination, totals/subtotals, saved filters, scheduled generation. **Totals are never fabricated** — every displayed figure traces to a DB calculation. Report implementations are shared with the per-module report rows (02-114…, 03-68…, 04-63…, etc.); this module provides the unified Reports hub, cross-domain custom builder, and scheduling.

**Built (13-01…13-09, 13-11, 13-12):** the centre at `GET /app/reports` and one hub per catalogue family, all driven by `Reporting\ReportRegistry` — a registry written *against the router*, not beside it. An entry names the route it lives on; the hub lists entries whose route this installation really registers, drops the rest, and reads each row's permission back off that route's own middleware instead of typing it a second time. Two consequences, and both are the point: a report that has not been built **cannot** appear on a hub (no dead doors), and a report that exists but whose key the reader lacks is still **listed, by name, saying which key it needs** — hiding it is how a manager concludes the system cannot do something it can. `planned` is how a family says what is missing and why, in words on the page, instead of an empty card that reads as a broken screen.

Also real: `report_definitions` + `saved_filters` + `report_runs` + `scheduled_reports` (§02-120's tables), `CustomReportBuilder` (whitelisted sources, re-validated on every run, branch scope applied at run time), `ReportRunService` (row count + snapshot + honest failure state), `ScheduledReportService` (frequency-validated schedule, next run, audit).

**Not built here, and why:** 13-10 Delivery reports (`Reporting\DeliveryReports` — COD totals, courier SLA, failed rate, rider performance) reads `shipments`, `tracking_events` and `rider_cod_collections`, and the delivery module's own desks are where that data is written today; the COD reconciliation desk already answers the money question, so the reporting class lands with the rest of §07. 13-13 — the unified export/print/PDF pipeline — needs the §19 document frame for print and PDF, and until then export is per report (CSV, same rows as the screen, filters included), which is what the report screens do rather than what this row will eventually do.
