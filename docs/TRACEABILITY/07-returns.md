# 07. RETURNS — Traceability

Baseline (`BL`) applies. Shared services: `Returns\Actions\{CreateReturnRequest, ApproveReturnPath (via Workflow), ReceiveReturnedGoods, InspectReturn, RestockReturn, ProcessRefund, CompleteRefund, DenyReturn, CreateExchange, ProcessExchange, AuthorizeSupplierReturn, CreateWarrantyReturn}` · `Returns\Services\{ReturnStateMachine, ReturnWindowValidator, InspectionService, RefundService}` · engines: Workflow, Inventory (`StockLedgerService` restock), Accounting (credit/refund postings), Warranty (void/repair effects), Documents, Notification, Audit.

Rule: posted returns/refunds never rewrite history — restock is a new inbound movement; refunds are new postings linked to the original invoice.

Core path DONE (gate `SalesRemainderTest`, 11): CreateReturnRequest → ReceiveReturnedGoods (SALES_RETURN inbound) → IssueCreditNote (inverse GL via `sales_credit_note_issued` + optional `sales_return` COGS reverse) → ProcessRefund (Dr ar / Cr cash via `refund` rule, idempotency). Return window config, WF approval, inspection disposition, exchanges, damage types, warranty claims, and reports remain PLANNED.
