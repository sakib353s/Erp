# 01. DASHBOARD — Traceability

Single page containing exactly **25 widget containers** (Spec §28/§48-A). Items 25+26 of the raw list (Branch Comparison, Recent Activity) are merged into one composite widget so both information areas survive while the count stays 25. Widgets are NOT menu pages. Widget definitions, order, visibility, and permissions live in `widgets`, `widget_permission`, `widget_user_visibility` (DB-driven, Spec §0.4).

Common backend for all widgets: `Dashboard\DashboardController@index` (page), `Dashboard\WidgetDataController@show` (AJAX data endpoint per widget slug), `Dashboard\Widgets\{Name}Widget` query services, `Dashboard\WidgetRegistry`, `Reporting\Aggregates\*` (pre-aggregated `bi_metrics_daily` + on-demand bounded queries with safe cache invalidation after commit). Every widget: branch/role scoped via ScopeContext, date-range params, refresh, drill-down route to authorized records, professional empty state when no data (never invented numbers), cached derived reads only.
